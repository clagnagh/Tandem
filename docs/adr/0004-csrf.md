# 4. CSRF defence for cookie sessions

Date: 2026-10-02. Status: Accepted. Spec: phase-1 question 4 and review
checklist.

## Context

Sessions are cookies, which the browser attaches automatically. A hostile
site could make the browser send a state-changing request to Tandem.

## Options

1. **CSRF tokens** (synchronizer or double-submit). Strong, but every form
   and fetch must carry the token.
2. **SameSite=Lax cookies plus an Origin check.** Lax stops cookies on
   cross-site POST, PUT, PATCH and DELETE. Checking the `Origin` header covers
   old browsers and same-site attacks from sibling subdomains.
3. **SameSite=Strict.** Breaks following a link to Tandem from email while
   signed in (for example invite links).

## Decision

Option 2. Cookies are `HttpOnly; Secure; SameSite=Lax`. Every request whose
method is not GET, HEAD or OPTIONS must have an `Origin` header equal to
`APP_URL`, or it is rejected with 403. GET requests never change state.
Better Auth's own origin check stays on.

## Consequences

- Built in Phase 1 step 4, together with an integration test that sends a
  POST with a foreign `Origin` and expects 403.
- Server-to-server callers (the public API in Phase 6) use API keys in a
  header, not cookies, so the check does not apply to them.
